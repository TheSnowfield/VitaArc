# Render bridge profiling, 2026-10-25

## Scope

The local Vita3K portable build runs Arcaea 1.6.1c with the Vita texture
profile. A separate portable filesystem contains private persistent data.
App/firmware inputs are linked read-only by convention; overridden package
resources are unlinked in the private copy before replacement. No installed
normal eboot or original saved data is replaced.

The diagnostic SELF links the Release objects with small wrappers for frame
steps, swaps, audio mixing and selected GL functions. GL function wall times
sample one call in 64. Frame/swap/mixer times are measured per call. The
diagnostic also counts live buffers and benchmarks 128 collection passes at
each 300-frame report. These measurements include instrumentation overhead
and host emulation behavior. They are not physical PSV CPU utilization.

Work sources are under `.llm/profiling/`; runtime evidence and snapshots are
under `build/cpu-profile-20261025/`. Only the normal Release SELF is shipped
as `eboot.bin`; profiling wrappers and synthetic touch are not linked into it.

## Matched selection scene

The steady scene is Vicious Labyrinth / Axium Crisis song selection, with
933 live buffers and no pending deletions. Both versions issue the same
per-frame workload:

| Operation | Calls per frame |
| --- | ---: |
| Draw | 129 |
| Buffer bind | 348 |
| Vertex attribute pointer | 266 |
| Buffer data | 42 |

`comparison.json` selects only 300-frame windows matching those counts,
933 buffers, zero pending deletions and a wall duration of 4.9–5.1 seconds.
There are 23 eligible windows / 6,900 frames per version in the snapshot.

| Metric | Baseline | Optimized |
| --- | ---: | ---: |
| Median window-average render wall time | 6,776.88 us/frame | 1,732.84 us/frame |
| Median 128 collection passes | 721 us | 2 us |

The render wall-time reduction is 74.43%. Display/vsync waits remain in the
separate swap measurement; a roughly 16.7 ms overall frame period does not
mean the CPU performs 16.7 ms of computation.

## Cause and implementation

The old bridge repeatedly walks the full ownership list during buffer
binding, attribute setup and deletion collection. A deletion collection
pass visits all 933 objects even when no object is pending deletion.
Attribute setup also reverse-searches the full list for a zero binding or
for the current array buffer, and queries the invariant attribute limit.

The new bridge separates three responsibilities:

- The ownership list retains every native buffer until its final release.
- A 256-bucket name index resolves guest buffer names. Rollback, physical
  release and shutdown maintain the index.
- A pending-deletion list contains only deleted objects. VAO references
  still retain their native objects; a reused guest name can coexist with
  the older retained object.

Native binding conversion returns immediately for zero or the current
array buffer. The maximum attribute count is cached for the single GL
context and reset during shutdown. Native post-commit queries and error
handling remain in place, including implementation-specific rejections.

This adds two pointers per buffer and 256 bucket heads: about 8.3 KiB for
the measured 933-buffer scene. It removes repeated full ownership scans
from the frequent paths without retaining extra GPU buffer payloads.

## Normal runtime diagnostics

`src/platform/perf.c` records render and presentation wall times, reports
their averages and maxima every 30 seconds, and counts render steps over
16,667 us. It runs on the render owner thread and allocates no memory.
Presentation includes GPU/display waits and must not be read as CPU usage.
The report permits a hardware boot log to distinguish long render steps
from long presentation waits.

## Startup display

The embedded PNG is decoded once into a 120x64 image. Its white matte is
removed with coverage preserved, then the image is drawn at the same pixel
scale as the text. It occupies ordinary scroll rows, followed by a blank
row and `LICENSE / Credits`. The logo data is released after the display
callback queue has drained. No additional installed file is needed.

Text newlines defer opening the next row until more text arrives. The
renderer retains 31 visible rows at 960x544, including the last populated
row. Smaller framebuffers show the most recent rows that fit. Ordinary
startup screen refreshes are limited to 15 FPS; errors refresh immediately.

PNG source is retained unchanged in `resources/branding/vitagl.png`.
`tools/embed_binary.py` produces the generated byte header during builds;
it does not perform image processing or source reformatting.

Preview artifacts: `intro-final.png`, `scroll-final.png`. Release and Debug
compile successfully. No unrelated regression suite was run. Device CPU
percentage, physical audio deadlines and device frame-time improvement
remain unmeasured.

The optimized diagnostic also enters Sayonara Hatsukoi Past 1, loads its MP3
and captures the rendered playfield in `gameplay.png`. Native logs continue
through the chart without `exception_handler`. This is execution/capture
evidence only; it does not establish physical audio quality, timing accuracy
or a matched before/after gameplay performance comparison.
